# Decisions and deviations from the concept

The concept (`Ruinborn – Spielkonzept v1.md`, German) is the binding specification. Wherever the implementation deviates
from it or had to settle an open question, the decision and its reason are listed here. Every entry is also noted in
section 20 of the concept.

| No. | Topic | Decision | Reason |
| --- | --- | --- | --- |
| E-01 | Project structure | Kotlin Multiplatform: `shared` (game rules, DTOs, balance) and `client` (HTTP, WebSocket, state) are KMP modules with code only in `commonMain`, for now with the `jvm()` target only. `server`, `core` (libGDX), `lwjgl3` and `tools` are Kotlin/JVM. | User requirement: KMP, but JVM only for now. Everything that can be platform neutral without restrictions is shared. libGDX, SQLite, Klogger and KotNexLib are JVM-only libraries. |
| E-02 | Android | Module `android` with launcher (OkHttp engine), manifest and signing as in the concept. `core` stays JVM 17 compatible, the HTTP engine is passed in by each launcher. (Postponed at first, added on 01.10.2026 at the user's request.) | The Android app is the actual target. "Focus on JVM" referred to the KMP targets, not to dropping Android. |
| E-03 | Logging in commonMain | Small facade `shared/Log` (sink lambda). The apps connect it to Klogger. | Klogger is a JVM library and cannot be used in commonMain. |
| E-04 | Versions | Latest stable versions as of 30.09.2026 instead of the versions in the concept: Gradle 9.8.0, Klogger 0.2.0, KotNexLib 4.4.1, Exposed 1.5.0, KTX 1.14.2-rc2 with the new Maven group `io.github.quillraven.libktx`. | Requirement "all versions up to date". Details in [DEVLOG.md](DEVLOG.md), section 1. |
| E-05 | Graphics | Instead of flat SVG placeholders, the supplied isometric assets (2:1, 128 × 64 diamonds). Base and world map are drawn isometrically. `base_layout.json` contains tile coordinates instead of pixel rectangles. Missing sprites are added in the same style with the included Python generator. `svg2png.sh` is dropped. | The user supplied new assets and explicitly asked to use them. One consistent style instead of a flat/iso mix. |
| E-06 | Source of the default balance | `shared/balance/balance.json` is the single source. A Gradle task embeds it as `DefaultBalance.JSON`. The server writes it to `balancePath` on first start (concept: `server/src/main/resources/balance.json`). | Tests, server, client and simulation are guaranteed to use the same values, without platform-specific resource loading in commonMain. |
| E-07 | Resource amounts | Amounts are stored as decimals (`REAL`) and always rounded down when shown. | **Error in the concept:** if fractions are dropped on every materialization, frequent actions lose the entire production (100 per hour and one action every 30 s would yield 0). Test `frequentMaterializationLosesNothing`. |
| E-08 | Additional balance keys | `timers` (2 build queues, 50 % refund), `reports` (30 days, page size) and in `combat` the counter table and the hospital order. `daily.resetTime` lives only in `config.json`. | Every number from sections 3 to 11 belongs in `balance.json`. These values had no key in the concept. |
| E-09 | Event `SHIELD_END` | Additional scheduled event for the system report "shield ended". | Section 11 requires reports at shield start and end. Without an event there would be no point in time for it. |
| E-10 | PvP hero experience | "Killed enemy units" = all losses of the other side (wounded or dead). | Concept section 7 counts every unit that has to leave the battle as a loss. Otherwise experience would depend on the opponent's free hospital capacity. |
| E-11 | Own PvP action | Ends beginner protection and the running shield (peace, recovery and admin shield), but not the inactivity shield. | The concept names peace shield and beginner protection. All shields live in one column `shield_until`. Whoever attacks should not stay protected. |
| E-12 | Map view | `GET /api/map` and `map_changed` return marches in the public view (without hero and troops). Own details are in `PlayerState`. | A single broadcast for everyone, no data leaks. |
| E-13 | Password iterations | `passwordIterations` in `config.json` (default 100,000 as in the concept). Tests use 10. | Fast tests. The value must not be changed after the first start. |
| E-14 | IDs | All ID columns use `AUTOINCREMENT`. | Otherwise SQLite reuses deleted IDs. A new event got the ID of one that had just been deleted and was removed along with it (found in a test). |
| E-15 | Registration | Separate rate limit of 10 per minute per IP (login stays at 5). | Protects the invite code without using up login attempts. |
| E-16 | `X-Request-Id`, `X-Client-Version` | Both optional. Without `X-Request-Id` there is no replay protection, without a version no 426 check. | Every command stays testable with `curl` (guiding principle, section 15). |
| E-17 | Inactivity | "Active" is measured by `last_active_at`, which is set on every `GET /api/state`. The inactivity shield ends there as well. | Sessions last 30 days. Without this, a friend playing daily without logging in again would count as inactive. |
| E-18 | Rallies | The travel time to the target uses the starter's logistics bonus. Participants must arrive strictly before departure. | The concept leaves open whose march speed applies. The starter leads. "Before the waiting time ends" means strictly before. |
| E-19 | New world | `--new-world` also deletes all sessions. | The next login creates the starting state. Existing sessions without game progress would otherwise cause errors. |
| E-20 | Balancing | The default balance keeps the concept's starting values. The simulation (`runSim`) gives the normal player HQ 10/15/20 on day 9/17/30 (target 7 to 10, 21 to 28, 45 to 60). Cost, time, gathering and drop values barely shift the late game because it is limited by the login rhythm (HQ, then wall, then HQ, strictly one after another). | According to the concept, fine tuning is part of M6 (beta with real data). The tool and the findings exist, see [DEVLOG.md](DEVLOG.md). |
| E-21 | Controls | Chat messages are reported or deleted by tapping (instead of a long press). Map zoom 0.5 to 3.0 because the isometric tiles are twice as wide as the 64 px assumed in the concept. | Same controls on desktop and touch. Whole zones stay visible. |
| E-22 | Desktop launch options | `--profile`, `--login`, `--register`, `--screen`, `--dialog`, `--screenshot`. | Several test accounts in parallel and reproducible visual checks via screenshot. |
| E-23 | Texts | `I18NBundle` in simple placeholder mode. `Fmt` formats numbers the German way beforehand (thousands separator dot). | No MessageFormat surprises with apostrophes and numbers. |
| E-24 | Additional DTO fields | `PlayerState` also contains `incoming`, `limits`, `openAllianceHelps`, `openGifts`, `nextDailyResetAt`, `gameSpeed`, `devMode`. Additional endpoint `POST /api/reports/read-all`. | The client does not have to recompute anything only the server knows. All fields have default values. |
| E-25 | Android build | AGP 9.1.0 instead of the newest 9.4.1. compileSdk and targetSdk 37 (instead of 36 from gdx-liftoff), minSdk 26. No shrinking (`isMinifyEnabled = false`). Server URL via `ruinborn.androidServerUrl`, otherwise `ruinborn.serverUrl`. | OkHttp 5.5 from Ktor 3.6 requires compileSdk ≥ 37. Shrinking would need extensive keep rules for libGDX, Ktor and kotlinx.serialization, and the APK is only about 7 MB anyway. The emulator reaches the host at `10.0.2.2`. IntelliJ IDEA only supports AGP up to 9.1.0, so the project stays usable without Android Studio. AGP 9.1 warns that it was not tested with compileSdk 37. Build and lint pass, so `android.suppressUnsupportedCompileSdk=37.0` silences the warning. compileSdk is declared as `release(37) { minorApiLevel = 0 }` so the target is `android-37.0`, matching the SDK platform folder. With plain `37` IntelliJ looks for `android-37` and cannot find it. |
| E-26 | Optional Android module | `:android` is only included if an Android SDK is found and `-Pruinborn.skipAndroid` is not set. | Server and desktop client build and test without an Android SDK (e.g. in CI). A failure in the Android module does not affect them. |
| E-27 | Back key | Closes the topmost dialog. Without a dialog it leads from the map to the base and does nothing in the base (Esc on desktop does the same). | No accidental exit. Common behavior in games of this kind. |
| E-28 | Client IP for rate limits | `X-Forwarded-For` only counts for connections from loopback or private addresses (Caddy). | Otherwise the login limit could be bypassed with a made-up header as soon as the server is directly reachable. |
