# Ruinborn v1: implementation plan

> **For executing agents:** implement with superpowers:executing-plans (natively, one session). Steps use checkboxes (`- [ ]`). No Git repository (user requirement at the time). Instead of a commit, every finished step is recorded in `docs/DEVLOG.md`.

**Goal:** Implement the game concept "Ruinborn v1" as a working Kotlin Multiplatform project: server (Ktor, SQLite), shared game rules (KMP), client network layer (KMP) and a libGDX desktop client with the supplied iso assets.

**Architecture:** All game rules (formulas, resources, combat, validation, DTOs, balance) live in `shared/commonMain` and can be tested without a server. The server processes all writes in a single-writer engine (one thread, one `Channel`). SQLite is the single source of truth. The client decides nothing: `client/commonMain` (Ktor client, WebSocket, state) is platform neutral, `core` (libGDX) renders and handles input.

**Tech stack (researched on 30.09.2026, latest stable version each):** Kotlin 2.4.20 · Gradle 9.8.0 · Amazon Corretto 25 (toolchain) · kotlinx.serialization 1.11.0 · kotlinx.coroutines 1.11.0 · Ktor 3.6.0 · Exposed 1.5.0 · sqlite-jdbc 3.53.4.0 · slf4j-api 2.0.20 · libGDX 1.14.2 · LWJGL 3.4.3 · KTX 1.14.2-rc2 (`io.github.quillraven.libktx`) · Klogger 0.2.0 · KotNexLib 4.4.1 · JUnit Jupiter via kotlin-test-junit5.

**Spec:** `Ruinborn – Spielkonzept v1.md` (in the project root). Deviations are listed in `docs/DECISIONS.md` and in section 20 of the concept.

## Global rules

- Package root `bayern.kickner.ruinborn`. Subpackages as in concept section 13 (`shared`, `server.api|engine|db|jobs|admin|sim`, `client.net|state|screen|ui|render`, `tools`).
- Code style: `runCatching` instead of `try/catch`, `.not()` instead of `!`, sealed classes. Expected errors in the server as `ResultOf2<T, GameError>` (KotNexLib), no exceptions.
- Every number of the game rules comes from `balance.json`. The server validates the file completely and does not start otherwise.
- Time only via an injectable `Clock` (ms UTC), randomness only via an injectable `Random`.
- Rounding: round costs/amounts/loot/capacities down, durations up (≥ 1 s). Combat values unrounded. Floating point guard: `floor(x + 1e-9)`, `ceil(x - 1e-9)`.
- Bonuses of the same kind are added. `gameSpeed` divides all durations except protection/shield durations, daily reset and maintenance jobs.
- `shared`, `client`, `core`: bytecode JVM 17. `server`, `lwjgl3`, `tools`: JVM 25.
- All texts in German. Client texts in `assets/i18n/strings.properties`.
- Only what works with KMP without restrictions goes into `commonMain` (no `java.*` imports there).

## Review focus

1. Player was offline for days, several timers finished, warehouse full → `settle` processes timers in order, production stops exactly at capacity (tests in task 4 and task 9).
2. Duplicate command with the same `X-Request-Id` → exactly one execution, identical response (task 8).
3. Server restart with running marches → overdue events processed in order of due time (task 7/12).
4. Daily reset on DST change days in `Europe/Berlin` → exactly one reset at 04:00 local time (task 11).
5. Leaving an alliance with a waiting rally march and a stationed reinforcement → both marches return home, gifts expire (task 14).
